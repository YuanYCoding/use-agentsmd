# 验证范围

## 隔离项目行为验证

2026-11-03，在本地隔离项目中由独立 Agent 按用户请求执行 Skill。以下记录描述已观察到的结果，不是跨模型性能指标，也不意味着所有真实项目都得到相同结果。

| 场景 | 观察结果 |
| --- | --- |
| 开工阶段，只有已确认需求 | 创建目标与首期范围；没有编造技术栈和命令 |
| 用户说明已上线，根文件缺失 | 按维护阶段创建；对演示发布配置与可用部署流程作出区分 |
| 包管理器及目录迁移 | 替换旧命令和目录，保留原有接口规则，说明现有检查范围 |
| 一次性按钮文案修改 | 原 AGENTS.md 内容和修改时间均保持不变 |
| 已有可用版本的 npm workspace，已有 Web 子规则 | 使用实际 npm 版本、包名、PR 要求和类型检查范围，保留正确的子规则 |

每个场景重复调用后，比较了说明文件的 SHA-256 与文件修改时间；已观察到重复调用没有无意义改写。验证中曾发现一条未来测试方案待办被留下，随后补充了区分当前检查范围与未来待办的规则，并重新验证该场景。

这些验证仅涉及文件维护、静态项目证据与文档差异，没有安装依赖、执行应用、运行项目测试或部署服务。案例用于发现决策问题，不构成生产可靠性保证。

## 仓库自动检查

```bash
python scripts/check_package.py
```

该检查覆盖：Skill 名称及必要字段、UI 名称一致性、本地 Markdown 链接、README 图片存在性、SVG 语法和发布必需文件。检查脚本使用 Python 标准库。

它不执行大模型，也不验证模型是否遵守指令。改变阶段判断、写入范围或规则筛选时，仍应做实际行为验证。

## 如何复验行为

1. 在临时目录准备一个最小项目，提供清单、文档及相关说明文件。
2. 记录原文件内容与修改时间。
3. 给支持该 Skill 的 Agent 一个真实任务，只授权修改测试项目的 AGENTS.md。
4. 检查新增规则是否有项目证据、原有有效规则是否保留、临时内容是否被排除。
5. 用同一事实再次调用，对比内容和修改时间。
6. 在记录中区分用户提供的状态、文件证据和实际运行结果。

下一步最有价值的验证是同一真实项目的持续使用，尤其是跨对话背景缺失、长期约定的局部适用范围，以及迁移期间新旧方案并存的情况。
