# AGENTS.md 内容生成参考

此文件用于选择和组织目标项目的工作规则。首次创建或调整结构时读取前两节；补充命令、模块规则或兼容性说明时读取对应小节。不要把本文件整体复制到目标项目。

## 定位与格式

- **官方定位：** 为编程 Agent 提供项目上下文和操作说明，与面向人的 README 配合使用。生成内容应帮助 Agent 定位、修改、验证和交付工作。依据：[Why AGENTS.md](https://github.com/agentsmd/agents.md/blob/d001185d792eb6402a58e4cbef1c228b309ec25d/components/WhySection.tsx)。
- **官方格式：** 普通 Markdown，没有必填字段或指定标题。不要要求生成的文件带 `name`、`description` 等 Skill frontmatter。已有项目采用的有效结构可以保留。依据：[FAQ](https://github.com/agentsmd/agents.md/blob/d001185d792eb6402a58e4cbef1c228b309ec25d/components/FAQSection.tsx)。
- **本 Skill 的写作方法：** 用简短标题、直接的动作说明和必要的代码块/表格组织信息。命令用行内代码或带语言标记的代码块；复杂背景引用原文档，说明什么时候阅读。根据已有信息提供足够具体的指导，不设统一字数或章节配额。
- **项目内容边界：** AGENTS.md 记录项目规则和必要背景。项目宣传、徽章、截图展示、聊天记录及本 Skill 的研究过程通常不属于这些规则；不要因为正在整理开源 README 就将宣传内容加入 AGENTS.md。

## 内容选取表

官方建议覆盖项目概况、构建和测试、代码风格、测试说明及安全注意事项，也列举了提交/PR 指南、大型数据集和部署步骤等可选内容。以下表格是本 Skill 对这些建议的操作化整理，所有行都是候选，不是必填项。依据：[官方使用说明](https://github.com/agentsmd/agents.md/blob/d001185d792eb6402a58e4cbef1c228b309ec25d/components/HowToUseSection.tsx)。

| 候选内容 | 先查什么 | 有依据时如何写 |
| --- | --- | --- |
| 项目目标与导航 | 当前确认的需求、README、入口及主要模块 | 用少量文字说明用途、阶段性范围和关键模块职责；指向需要阅读的设计或业务文档 |
| 环境与依赖 | 项目清单、锁文件、版本文件、配置模板、开发说明 | 写实际工具、必要版本约束、安装/启动入口及前提；存在多份锁文件时先辨明当前约定 |
| 构建与运行 | 构建脚本、任务配置、开发服务器说明 | 区分开发运行、生产构建和预览；记录目标项目确有的互斥操作、生成产物或重启要求 |
| 编码与复用 | 格式化/静态检查配置、明确团队规则、代表性现有实现 | 写可操作的命名、类型、导入、异常或复用约定；引用关键组件/工具；个别代码风格只能作线索 |
| 测试与验收 | 测试目录、脚本、CI、贡献指南 | 写相关改动要运行的检查、工作目录、范围和必要前提；区分单项检查与完整验证 |
| 提交与 PR | CONTRIBUTING、PR 模板、提交校验配置、用户明确约定 | 按实际要求记录标题/提交格式、变更说明和必需检查；没有约定时不发明格式 |
| 安全、数据与特殊文件 | 已有安全约束、配置模板、数据说明、生成器及相关文档 | 记录有证据的敏感配置处理、数据准备、生成文件修改方式、外部服务或成本前提；只写影响实际工作的要求 |
| 部署与运维 | 发布脚本、工作流、运行手册、环境说明 | 指明入口、适用环境、前置验证和执行边界；有依据时链接回滚与故障处理说明 |

阶段决定本次重点，证据决定可以写到多具体。成熟项目首次补建时，可选择多类内容；刚开工时只有目标和已确认边界也可以形成有效文件。

## 命令与验证规则

官方 README 示例展示了开发环境提示、按包测试、聚焦某项测试、查阅 CI 和 PR 检查等写法。它表达的是具体、可操作的指导方式；其中的 pnpm、Turbo、Vitest 及命令参数需要按目标项目重新核实。依据：[README 示例](https://github.com/agentsmd/agents.md/blob/d001185d792eb6402a58e4cbef1c228b309ec25d/README.md)。

生成每条关键命令时核对：

1. **命令来源与用途：** 从实际脚本、任务配置或项目说明确认。脚本存在只能证明已定义，不能证明当前环境能够成功运行。
2. **工作目录与目标：** 说明从仓库根、某个包或服务目录执行。workspace/filter 参数应使用实际包名；包名可能与目录名不同。
3. **必要前提与条件：** 只补充会影响执行的环境变量名称、配置模板、数据准备、服务依赖或平台差异，不嵌入真实凭据和维护者个人路径。
4. **触发时机与检查范围：** 说明什么改动需要此检查，以及它覆盖类型、语法、单元测试、集成测试或构建中的哪一项；不要用一次构建成功代替全部验收。
5. **失败后的要求：** 沿用项目已有策略，报告相关失败、未执行项及原因；不能把跳过检查写成默认处理方式，也不能声明检查必然通过。

“为行为变化补充适当测试”应结合用户要求、项目规范和现有测试能力采用，不把官方样例中每次修改都加测试或总跑全套检查的语句推广到所有项目。

**写法示例：** 假设已核实根 `package.json` 中存在 `check` 脚本，内容仅为检查一个入口文件的 JavaScript 语法，可以写：

```markdown
## 验证
- 在仓库根目录运行 `pnpm check` 检查入口文件语法。
- 此检查不覆盖业务流程；本次改动的其他验证以项目现有流程为准，并在交付时说明实际结果。
```

该示例仅说明“目录、用途、覆盖范围”的表达方式；目标项目的包管理器、脚本和验证要求应来自该项目。

官网 FAQ 描述 Agent 会尝试执行文档列出的相关检查。本 Skill 负责维护说明，不能因此把本次文档维护扩大成安装、全量测试或部署任务，也不能承诺其他工具一定自动执行。依据：[测试 FAQ](https://github.com/agentsmd/agents.md/blob/d001185d792eb6402a58e4cbef1c228b309ec25d/components/FAQSection.tsx)。

## 根目录、子目录和文档引用

官方建议从根 AGENTS.md 开始，大型 monorepo 可增加子项目文件；官网用更接近被编辑文件的规则优先来解释冲突。该说明不能替代具体宿主工具的加载实现。

本 Skill 采用以下组织方法：

- 根文件放公共约定；只在模块有实际差异时新增子目录文件。根文件不需要列出每个子文件，只在有助于定位时给出入口。
- 子文件说明自身范围、命令和特殊约定。出现冲突时明确适用范围，避免让读者误以为根文件的其他有效规则全部失效。
- 文档链接相对当前 AGENTS.md 所在目录解析，并明确命令的工作目录。将文件移动到子目录时，同步检查链接与命令上下文。
- 关键约束直接写出；冗长流程引用拥有该内容的文档，并给出阅读触发条件。不要只给一个缺乏任务指引的链接，也不要复制整份文档制造两份需要同步的规则。
- 新文件使用可跨机器的项目相对路径。已有本机专属入口只有在本次范围需要迁移时才调整；不要把维护者个人目录写进供团队使用的新规则。
- 用户当前要求与项目约定不一致时，按宿主实际指令层级处理。一次任务中的明确例外不自动变成永久规则；官网 FAQ 的概述不授予任何额外工具或外部操作权限。

依据：[嵌套文件说明](https://github.com/agentsmd/agents.md/blob/d001185d792eb6402a58e4cbef1c228b309ec25d/components/HowToUseSection.tsx)、[冲突 FAQ](https://github.com/agentsmd/agents.md/blob/d001185d792eb6402a58e4cbef1c228b309ec25d/components/FAQSection.tsx)。

## 官方仓库的规则只适用于该仓库

`agentsmd/agents.md` 同时包含介绍网站及示例。它的根 AGENTS.md 指导网站开发，包含开发服务器、依赖变更后的锁文件和重启处理、TypeScript 等具体约定，还限制交互开发期间执行生产构建。

可以借鉴其写法：**操作规则 + 适用场景 + 原因 + 正确做法**。不能由此推导所有项目都使用 Next.js、TypeScript，或所有 Agent 会话都禁止构建。

该文件还列出“存在测试套件时运行测试”的条件说明；本次核对的 `package.json` 没有 `test` 脚本。这说明即使使用官方示例，也需要检查实际脚本与条件，不能把提到的命令当作已经可运行。

依据：[官方仓库自身 AGENTS.md](https://github.com/agentsmd/agents.md/blob/d001185d792eb6402a58e4cbef1c228b309ec25d/AGENTS.md)、[对应 package.json](https://github.com/agentsmd/agents.md/blob/d001185d792eb6402a58e4cbef1c228b309ec25d/package.json)。

## 兼容性、旧名称和参考更新

- 官网列出了兼容工具，并为 Aider、Gemini CLI 提供配置示例。因此不要宣称所有工具都零配置、相同层级或实时重载。只有任务涉及特定工具接入时，再核对该工具当前官方文档。
- 官网展示了通过重命名和符号链接保留旧入口的迁移方法。它是可选做法，不能在普通内容更新中直接执行；须结合操作系统、已有引用与用户迁移范围处理。
- `@文件` 导入、工具专属全局目录等应按具体宿主处理，不作为 AGENTS.md 通用必备格式。
- 官方链接、核对日期和示例出处属于本参考文件；目标项目通常无需附上这些研究资料。官网采用数量、Star 数和工具品牌列表也不应成为目标项目规则。
